FeatureSearch engineering

Your users choose the filters. Should you design an index for every combination?

Kiara is an open-source, in-memory search library for Java and TypeScript. Load your records, call prepare() once, and search by any mix of fields, with typo correction and type-ahead built in.

01
In focusData structures

Ten filter fields. 1,023 possible combinations.

Based on KapoorLabs' engineering article, October 2026

Every field you add to a filter panel doubles the combinations users can pick. Exact-key lookups need one key per combination. Composite indexes cut that down, but each one only serves its leading columns.

Kiara keeps one index per field and joins them at query time. Records are stored as paths in a tree, nodes are numbered, and conditions combine with integer range checks.

1,023exact-key lookups needed for 10 fields
252composite ordered indexes, each limited to its leading columns
10per-field indexes, combined per query. This is Kiara's approach, built by one prepare() call.

Source: "Your data has 10 attributes...", KapoorLabs on dev.to

02
Explainer

Three things a plain loop can't do.

A hand-written filter can match exact values. Users type faster and less carefully than that.

"wireles hedphones" still finds wireless headphones.

Fields marked oneEditAway accept one wrong, missing or extra letter per word. The result tells you what was corrected, so your interface can show it.

Plurals work too. With stemming, "laptops" finds laptop.

keyword-search.tsexample
// mark the field once
textField("name", { oneEditAway: true, stemmedIndex: true })

keywordSearch.bestMatch("wireles hedphones")
// correctedKeywords:
{ wireles: "wireless", hedphones: "headphones" }

Suggestions while the user is still typing.

A dictionary trie predicts whole words from the first letters. Type "wi" and get "wireless". It's the same data structure the search uses, so there's nothing extra to keep in sync.

autocomplete.tsexample
const dictionary = new DictionaryTrie();
dictionary.addText("wireless headphones");

dictionary.predict("wi", 5)
// → ["wireless"]

Equality, ranges, lists and dates, in any mix.

Users pick filters in unpredictable combinations. Kiara answers each one from the same prepared store, with no index planning per query.

search.tsexample
store.search([
  createCondition({ field: "category", operator: Operator.EQUAL, values: ["laptop"] }),
  createCondition({ field: "price", operator: Operator.BETWEEN, lowerValue: 300, upperValue: 900 }),
  createCondition({ field: "tags", operator: Operator.CONTAINS_ALL, values: ["usb-c", "eco"] }),
]);
